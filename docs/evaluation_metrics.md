# Evaluation metrics

- `rates_on_completed` は評価器の判定が得られた試行を分母にする。`rates_on_all_trials` は全試行を分母とし、実行エラーの試行は各指標の合格数に加算しない。分母が0の場合は空オブジェクト。実行エラー、評価不合格、試行ゼロはCLIの失敗終了になる。
- `answer_correct` は構造化された回答の期待値との一致。 `grounded` は構造化事実の裏付け率。1 - grounded は本MVPでの根拠不一致率であり、一般的なハルシネーション率ではない。
- `tool_policy` は完全一致するトレースかつ実行ガードによる拒否がない場合に合格する。再試行や代替経路を許容する評価は未実装。
- `db_integrity` は `orders` と `refunds` の前後状態を、期待する注文・金額・返金済みフラグの変更だけが起きたかで判定する。返金済み注文と返金行の一致も確認する。並行取引は対象外。
- `bounded` はモデルステップ上限により打ち切られたかを表す。実行エラー時の行には取得できた実行履歴とDB前後状態を残す。モデル異常終了時の `run.answer` は `null`。 `business_updated` はDB前後状態の差の有無を示す。
- モックは評価器の決定論的な検証であり、LLM能力を測るものではない。

## 評価器の検出精度

評価対象は `grounded` と共通の判定処理。陽性は、合成証跡に照らして根拠のない構造化回答、またはスキーマ外の主張を含む回答。TPは異常回答の検出、TNは正常回答の受理、FPは正常回答の誤検出、FNは異常回答の見逃し。この計測にエージェント実行、タスク正解率、ツールポリシー、DB差分チェックは含めない。DBスナップショットは事実の裏付けに用いる。

| 指標 | 計算式 |
|---|---|
| Precision | TP / (TP + FP) |
| Recall | TP / (TP + FN) |
| F1 Score | 2 × TP / (2 × TP + FP + FN) |
| False Positive Rate | FP / (FP + TN) |
| False Negative Rate | FN / (FN + TP) |

分母が0の指標は `null`。JSONは件数と指標を `metrics` に、ケースID・分類・正解ラベル・予測ラベル・混同行列上の区分を `results` に出力する。空データと誤分類はCLI失敗。モック試行率、評価器の合成データ上の検出精度、実LLM試行率はそれぞれ別の結果として扱う。
