# Test strategy

1. 決定論的テスト: fixtureで既知のツール経路と異常を再現し、評価器自体の検出力をテストする。
2. 実LLM評価: 同じシナリオを実モデルに渡し、独立した期待値・実行ログ・DB状態で評価する。モックの合格率と混ぜない。
3. 回帰: モデル・プロンプト変更前後に同じケースで複数試行し、モデルID、試行数、エラー件数、評価結果を比較する。
4. CI: PRとpushで決定論的テストを実施。実LLMは費用・再現性の都合から手動のみ。

優先リスク: 虚偽の返金成功、無断返金、二重返金、権限違反、架空データ、停止不能。

CIではpytest、モック評価、手動ラベル付き合成データによる評価器精度測定を実行する。精度測定では固定データの誤検出・見逃しを許容せず、モック試行結果と別のJSONを保存する。
